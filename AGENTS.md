# Bailey Tucker: instructional design portfolio site

A static website hosted on GitHub Pages. There is no build step: every file in the repo is served as-is, and a push to `main` publishes the site within a minute or two.

## What's where

| Path | What it is |
| --- | --- |
| `index.html` | Home page: intro, featured course, links to project materials |
| `design-process.html` | Write-up: the ADDIE process and adult learning theory behind the samples |
| `work-samples-note.html` | Write-up: why current work is proprietary and how these samples were anonymized |
| `assets/site.css` | Shared styles for the three pages above (palette and fonts are tokens at the top) |
| `assets/course-preview.webp` | Screenshot of the course used on the home page |
| `course/index.html` | The self-paced eLearning course, a single self-contained file (its own CSS and JS) |
| `course/img/` | Mock-up screenshots used in the course (fictional data) |
| `samples/` | Downloadable files: the design document PDF and the original PowerPoint prototype |
| `tools/` | Scripts that regenerate the mock-ups and the design document. Not served as pages; only needed to change those files |
| `.nojekyll` | Tells GitHub Pages to serve files as-is. Keep it |

## Editing the course

Course content lives in two JavaScript arrays near the bottom of `course/index.html`:

- `LESSONS`: each lesson has an `id` (used in the URL hash), `title`, `kicker`, `sub`, and a list of `blocks`. Block types: `text`, `note`, `facts`, `map`, `img`, `cards` (flip cards), `acc` (accordion), `tabs`, `process` (step-through), `video` (placeholder), `kc` (knowledge check, `a` = index of the correct option).
- `QUIZ`: the 10 posttest questions. `o` = objective number, `a` = index of the correct option, `ex` = exhibit image name in `course/img/` (no extension).

Answer keys must match what the exhibit images actually show. If you change an answer or an image, check both.

## Rules

1. **Confidentiality comes first.** This project was originally done for a real employer. Never add the real company name, internal system or tool names, location codes, colleagues' names, real screenshots, or real screen recordings. All system screens must be mock-ups with fictional data, generated by `tools/mockups/gen_mockups.py`.
2. **Keep it static.** Plain HTML, CSS, and vanilla JS. No frameworks, bundlers, or build steps for the site itself. Relative links only (the site must work at the domain root and when opened locally).
3. **Keep it accessible and responsive.** It must work at phone width (about 400px), in light and dark mode, and with a keyboard. Images need meaningful `alt` text. Keep color contrast at WCAG AA.
4. **Use the shared tokens.** Colors and fonts come from the CSS variables in `assets/site.css` (and the matching block at the top of `course/index.html`). Don't hard-code new colors.
5. **Write plainly.** First person, as Bailey. Short sentences, active voice, no buzzwords. Don't invent experience, credentials, results, or employers.
6. **Don't commit originals.** The unredacted 2022 coursework files must never be added to this repo. It's public.

## Previewing locally

Open `index.html` in a browser, or run `python3 -m http.server` in the repo root and visit http://localhost:8000.
